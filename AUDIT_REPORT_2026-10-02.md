**Scope:** Web/PWA, Android Capacitor shell, iOS wrapper and iOS web use, Quran and supporting content, local persistence and backup, API integrations, Supabase functions/database integration, auth/sync, notifications/widgets, build/release configuration, dependency health, and store-readiness constraints.

## Executive assessment

The app has a substantial offline-capable feature set, and its existing visual design remains intact. This audit fixed regressions across Quran navigation, persistence and restore, prayer-time fallback, auth callback delivery, sync lifecycle, audio, reminders, widgets, content handling, accessibility, and privacy disclosures. The latest local `npm run verify` on 2026-10-04 passed **1,287 tests in 172 files**, with **86 lint warnings and zero lint errors**; TypeScript and the production/PWA build passed. On `5ac6fe1`, [Pages validation](https://github.com/xgharibx/ATHAR/actions/runs/37176801493), [Android validation](https://github.com/xgharibx/ATHAR/actions/runs/37176801483), and [iOS build](https://github.com/xgharibx/ATHAR/actions/runs/37176801428) all passed. Android CI installed dependencies and compiled/linted the postinstall-patched Capacitor sources. The legacy Hadith migration waits for one atomic IndexedDB import before allowing the old snapshot to be replaced; failures retain the version-24 source for retry. Browser color checks confirmed at least **5.32:1** contrast across all 30 theme/day-phase accent declarations and the selected custom accent. All **14 Android API 36.1 instrumentation tests** passed in the latest audit run, including cold/warm widget routing, route replacement, and the full prayer widget's live countdown and legacy fallback. The current source and generated debug/release manifests request only user-granted `SCHEDULE_EXACT_ALARM`; interactive widget mutations use a private receiver and reject uninstalled widget IDs. On 2026-10-03 the live Supabase project became reachable: five non-destructive access, quota, and RLS-performance migrations were applied, Companion v9 adds a shared daily spend reservation, Dorar protection and account-deletion updates were deployed, and direct leaderboard table/view reads were closed. Anonymous Companion requests still fail with 401 before any paid provider request. **The revisioned sync client and its additive backend protocol are deployed.** The web client rejects individual sync documents above 4 MiB and batches above 5 MiB before sending, preserving local data and showing a non-retrying error. Matching server caps and pgTAP checks are prepared under `supabase/release-gates/`, but remain unvalidated and unapplied until a disposable database is available. Legacy direct writes remain enabled for compatibility. Signed-in multi-device round-trips remain unverified; there is no evidence here that a user attempted sync before the protocol migration was applied. The full dependency audit reports 15 development-tree advisories (1 critical, 13 high, 1 moderate); `npm audit --omit=dev` reports none. The build continues to warn about browser-externalized Anthropic SDK modules, `lottie-web`'s `eval`, mixed static/dynamic imports, stale Browserslist data, and chunks above 900 kB.

The app is **not ready for a public store release**. Remaining gates include signed-in end-to-end verification, the still-undelivered Quran translation service, the pending leaderboard identity guard and self-reported score model, Sign in with Apple while Google is offered, accurate provider privacy/retention and store disclosures, the non-bootstrappable migration chain, iOS device/store preparation, an explicit Android backup policy, and signed release artifacts. Companion now has a shared $1/day estimated reservation ceiling and a 250-request daily cap; signed-in live flow and provider-cost reconciliation still need verification. The account-deletion function is updated in production, but no real user deletion was performed. The unsigned macOS 26/Xcode build passed on c24faa3, but iOS device round-trips remain open. Android CI packages an unsigned release AAB for review and checks platform version parity; candidate version code 77 is above live code 74, but a signed artifact is still required.
